# Synthetic full Interview Prep journey acceptance

**Scope:** PREP-BRIDGE-001 / [Interview Facilitator #105](https://github.com/LowcountryDigitalWorks/interview-facilitator/issues/105). This source-only test joins already accepted **pure** preparation modules on current 1.3 main. It adds no runtime UI, new storage/provider adapter, client records, SDK or dependencies. Existing PR #116 (private handoff), #117 (human action staging) and #118 (fresh-profile browser recovery) are separate, still owner-gated drafts; this test does not change any of their paths.

## What the single journey proves

1. A synthetic packet containing conflicting private source candidates is converted to **human review**, never a recorded answer. Owner Console projection remains generic **waiting**, with no client name, source pointer, proposed values, private notes, job/session/revision IDs or fabricated protected launch.
2. An exact-digest human selection creates a **private unconfirmed overlay**, without modifying the canonical interview or public read-back.
3. A **separately entered client statement** and explicit operator attestation produce a proposed new 1.3 revision, with parent linkage and source set to `client-statement`, not the research source. Private research source references do not enter the confirmed session.
4. A synthetic in-memory full-canonical compare-and-save gate approves exactly one proposed revision. Replaying the same old packet against the updated session fails, as does replaying the old store expected canonical state. No provider mutation is performed.
5. An independently human-drafted follow-up action remains **private and review-only**; an unresolved conditional question's retained follow-up is excluded. Ordinary canonical JSON serialization and semantic validation retain the internal state. **After the confirmed revision**, a newly constructed, explicitly revision-pinned *synthetic* no-evidence preparation packet is reviewed separately, and the resulting new Owner Console projection remains sanitized with **unknown**, `link-only`, and `launch.available=false`. This replaces reusing the earlier pre-confirmation status object.
6. Editing any input source values, private notes, client-attestation flag or engagement/job ID without re-review fails closed.

## What this does NOT establish

Neither this synthetic refreshed packet nor its projection establishes a real post-commit refresh, provider events, data freshness or a transition to operational `READY`. In the absence of newly authorized source evidence, the generic status deliberately returns `unknown`; never infer readiness from the existence of a confirmed answer.


Neither the synthetic store nor an affirmative flag proves authenticated operator identity, customer consent, correct client/engagement access, issuer authenticity, secure off-device backup, origin binding, destination-side atomicity/idempotency, actual SuiteDash Interview Prep stage event, provider availability, ClientOps automated write, Client Portal delivery, protected Owner Console launch, physical Safari/iOS/assistive-technology acceptance or real-client pilot permission. An imported session may fork to a new local revision; actual lineage-safe off-device recovery is still tracked under #35. The test intentionally makes no claims about production workflow state, external side effects, transport encryption, storage retention or legal authorization.

**Cost:** $0 incremental; offline/test synthetic only. No external APIs, credentials, user/customer records, installations, production changes or additional persistent infrastructure.

**Gates:** exact-head hosted CI and independent author-excluded review on this new test-only PR; then existing Interview Facilitator Product ORCH acceptance and applicable source/security/merge rules. No author self-merge.
