# Synthetic private preparation review — local PWA trial

Status: **source-level trial only**. [PREP-BRIDGE-001 #105](https://github.com/LowcountryDigitalWorks/interview-facilitator/issues/105). No customer/client pilot, provider source, authentication, Owner Console launch, CRM trigger, background upload or approved private storage path is implied.

## Narrow live 1.3 experience

In a local interview whose project label begins with `SYNTHETIC `, choose **Review interview** and then explicitly **Exit presentation** to enter **Private Review** (Presentation intentionally hides all internal tools). The Private Review screen offers a local **Load synthetic preparation JSON** control. The packet must be ordinary bounded JSON, with `jobKey` beginning `SYNTHETIC-`, and every evidence candidate must use a `SYNTHETIC ` value and `SYNTHETIC-` source reference. A maximum 512 KiB local file is read in tab memory and checked against the **selected exact session and pack revision**. Other/mismatched/malformed files are rejected without writing or retaining answers. The file is never uploaded or saved to IndexedDB, service worker cache, URL, GitHub, or an external provider. The trial is not shown for ordinary client sessions.

The existing private review component renders conflicting source values using DOM `textContent` and does **not** choose facts automatically. A human can select candidate IDs and check an explicit acknowledgment to exercise a transient **proposal requiring separate client confirmation**. The selection then opens a **separate synthetic client-confirmation form**. Nothing is prefilled into the statement box from the source candidate. The interviewer chooses one of the selected questions, independently enters what the synthetic client actually confirmed, and checks an explicit in-interview attestation. Only then can **Save synthetic client-confirmed answer locally** write a single canonical answer. The answer's source is `client-statement`, never the research candidate; the proposed value and source reference never enter canonical JSON, private exports or client Read-back. There is no task, message, provider write, CRM update, external consent event, or completed-interview flag.

**Native local save boundary:** The selected source and session remain pinned to their exact full canonical state. Before a save, pending normal autosave is flushed; a separate strict IndexedDB transaction compares the **entire stored canonical session**, archives the exact prior revision in `revision-history`, and writes one new revision with an explicit `parentRevisionId`. A stale tab, concurrent same-revision edit, changed source/pack, previously answered question, divergent proposal, or revision-history collision fails without claiming success. A successful save is a **local synthetic interviewer-entered statement**, not verified client identity, customer consent, or a production-grade synchronized record. Export and actual secure off-device archival remain separately gated under #35.

**Navigation boundary:** Returning to the interview, opening another session, switching to Presentation, or re-rendering Review disposes the private candidate and confirmation widgets, removes typed but uncommitted content, and clears the loaded packet and selection from app state. Stale asynchronous file reads are invalidated. An explicitly submitted atomic save may still complete once committed; navigation does not turn that consented local transaction into a remote action. Presentation shows no import control, source values, source references, or reviewer choices; exiting Presentation does not restore discarded content. The operator must select a fresh local file to repeat the trial. A dedicated Discard action clears the trial without changing the interview.

## Synthetic packet shape

The accepted `ldw.interview-prep.v1` packet fields are `schemaVersion`, `jobKey`, `sessionId`, `expectedRevisionId`, `expectedPackDigest`, `preparedAt`, and `candidates` containing `candidateId`, `questionId`, `proposedValue`, `sourceSystem`, `sourceRecordRef`, `observedAt`, `confidence`. A demonstrator can obtain the current session/revision/pack digest from a *synthetic* local canonical session backup. Only source-safe synthetic fixtures should ever be used. File size and markers are trial safeguards, not a complete DLP classification or approval to use real customer records.

## Unproven deployment and pilot gates

No authenticated actor↔client↔engagement authorization; no SuiteDash stage-event/source allowlist/private packet provenance pipeline; no *automatic* imported research confirmation (only separately human-entered synthetic statements); no provider idempotency; no protected private host/Owner Console link; no off-device encryption or revision-lineage restore; no physical Safari/iOS or screen-reader certification, and no production/customer approval. The offline-first interview still works with zero network. Future real-client integration requires separate independently reviewed, consent-bound private adapter and approved source/destination security before any live confidential data is used.
