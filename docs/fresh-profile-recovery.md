# Synthetic fresh-profile 1.3 restore acceptance — browser proof

Owning gates: [Interview Facilitator #35](https://github.com/LowcountryDigitalWorks/interview-facilitator/issues/35), [#105](https://github.com/LowcountryDigitalWorks/interview-facilitator/issues/105), [business-operations #753](https://github.com/LowcountryDigitalWorks/business-operations/issues/753).

This additive, source-only Playwright proof drives **the existing live 1.3 PWA interface**, not a new importer or provider. Chromium context A creates a synthetic interview, drafts a proposed follow-up/owner/free-text suggested date and confidential question/running notes, waits for native IndexedDB persistence, enters Review, confirms Presentation excludes export, and downloads **Export full JSON backup** only from private view. A distinct Chromium browser context B starts with empty storage, imports that exact local JSON file through the actual Home **Import session JSON** picker, verifies local storage and UI after reload, and checks that all pinned pack facts, canonical answers, internal notes and draft actions were carried into the fresh profile. The original profile remains independent. A separate negative test confirms a wrong pinned pack digest triggers an error and does not write a new session.

**Observed contract / important limitation:** the current import path uses `saveSession(..., null)`, which assigns a **new local revision ID** and null parent instead of retaining the exact exported revision lineage. The test deliberately asserts this behavior; a cross-profile transfer is *not* byte-exact archival restoration or proven history recovery. Any future schema 1.4 lifecycle/backups and authorized ClientOps workflow must explicitly reconcile revision and origin identity, preserve provenance and verify destination idempotency before promotion. Suggested free-text due dates are preserved, **not normalized or scheduled**.

This is an automated **two-isolated-Chromium-profile synthetic proof** only. It is **NOT** a physical second device, secure off-device backup destination, encrypted/approved private storage, iOS Safari or accessibility certification, user identity/client consent, transfer authenticity or production deployment. Canonical JSON is unencrypted and unsigned, and the pack digest detects mistakes rather than adversarial alteration. Do not use real customer records or publish downloaded private files in tests, GitHub or CI.

No changes to `main.ts`, `storage.ts`, import behavior, external providers, customer data, authorization, dependencies, license or operating cost. PR #116 private handoff bundle and PR #117 operator action staging remain separate draft source candidates under Product ORCH gates. $0 incremental.
